tasks: crispr-screen, rnaseq-confound, trio-liftover, flow-compensation, variant-review, hcs-dose-response,
       xlms-model-selection (seed 1, level 4); up to five agents ran at the same time

Sealing method (differs from batches A-C):
  Batches A-C encrypted the repository and deleted the plaintext. This time the agent harness refused the deletion of
  the working directory without a person's approval, and nobody was there to approve. The check was not worked around.
  Instead (pipeline/pilot_isolation/seal_overlay.sh, unseal_overlay.sh):
    1. the access time of every file and directory under the sealed trees was reset to 2026-01-01
       (ext4 relatime: the next read of a file or listing of a directory sets it to the current time);
    2. each tree was hidden under an empty tmpfs mount, so nothing on the host could reach it by path;
    3. at unsealing, the mounts were checked to be still in place and every entry with a changed access time was listed.
  Both scripts were dry-run first on a throw-away tree, including a simulated read (unmount, read one file, remount),
  which the audit reported.
  This is tamper-evident, not tamper-proof: a process that deliberately unmounted a tree could read it, and the audit
  would show which files. Encryption (batches A-C) also prevented such a read.
