# ALE life-science gym：可扩展的长程 agent 造题流程，和用它造出的 15 道难题

这个仓库回答一个问题：**怎样大规模地构造长程 agent 的训练数据，而且每道题的答案是对的、分数刷不上去、难度是量出来的。** 它包含三样东西：

- 一条造题流程（`pipeline/`，包名 `alegen`）：把一个专业工作流写成一个可以按随机种子和难度档无限出题的“家族”，每道题自动过八道关卡。
- 用它在 life-science 领域造出的 15 道 Harbor 题（`tasks/`），形式对齐 Agents' Last Exam（ALE）。
- 六个 flash 档模型在这些题上的实测结果和全部原始记录（`results/`）。

> **先说结论。** 流程已经在 10 个家族、7 个难度档上产出了 77 个通过全部关卡的实例，单个实例过关卡的中位耗时是 4.4 分钟，十个家族里八个由 agent 按规范写成。这里收的 15 道是其中最难的：gemini-3.8-flash 第一次尝试一道都没过，其中 13 道两次尝试都没过；别的模型做出了其中 6 道，所以题是可解的。让题变难的只有一类设计：**少一个没人提醒的专业步骤，流程照样跑通、结果看着合理**。
>
> 这 15 道是按“标尺模型做不出”挑出来的，所以 0/15 不是对整套题的无偏估计。全部 37 道题的分数、三轮实验的完整过程在 `REPORT.md`。

## 1. 仓库里有什么

```
README.md            本文
REPORT.md            完整报告（三轮实验的全部过程和数字；WORKLOG 和 docs 里说的“README 第 N 节”指的是它）
WORKLOG.md           按时间记录的工作过程，含失败与返工；各家族细节在 worklog.d/
tasks/               15 道 Harbor 题（instruction.md / task.toml / environment / solution / tests / README.md 题目卡片）
pipeline/            造题流程 alegen：家族生成器、放行关卡、难度筛选、Harbor 打包；AUTHORING.md 是出题规范
docs/                家族设计说明（真值模型、容差依据、已知弱点）、设计规格、全部 37 道题的总表 TASKS.md
results/validation/  每道题的放行记录（每个探针和攻击的得分）
results/jobs/        Harbor 跑分的原始记录（轨迹、评分明细、模型交出的文件）；results/difficulty/ 是难度筛选的判定
pack/tasks.txt       这 15 道题的清单
```

在一台能联网的机器上跑一道题（题目目录不依赖 `alegen`，任何支持 Harbor 格式的框架都能直接运行）：

```bash
harbor run -p tasks -a gemini-cli -m <模型名> -o results/jobs --job-name flash -k 3
```

用流程再出一道题并过关卡（生成器是字节确定的，同一个种子永远生成同一道题）：

```bash
cd pipeline && ../.venv/bin/python -m alegen make crispr_screen --seed 7 --level 6
```

## 2. 造题流程：怎样大规模构造长程 agent 的训练数据

### 2.1 出发点：ALE 的三件事不能照搬

ALE 是真实职业工作流的长程评测：agent 只拿到任务描述，在虚拟机里用专业软件工作几十分钟到几小时，交出的文件由脚本对隐藏参考答案评分。它的题很好，但出题方式不适合做训练数据。

| ALE 的做法 | 做成训练数据时的问题 | 本流程的对策 |
|---|---|---|
| 专家投稿加五道人工关卡 | 产量受专家数量限制 | 一个专业工作流写成一个**家族**（生成器），按种子和难度档无限出题；关卡全自动 |
| 参考答案是公开数据集的真值或专家跑出的结果 | 答案可查（Epoch 抽查 50 题，22 题可走捷径满分）；参考流程错了答案就错了 | **先埋真值，再造数据**：答案是植入的量，不是任何流程的输出，网上查不到 |
| “agent 看不到评分器，所以不会利用漏洞” | 强化学习会在成千上万条轨迹上主动找奖励漏洞 | 评分器**先过攻击测试再放行**；隐藏真值只存在于独立的评分镜像里 |

ALE 自己的失败分析指明了该练什么：失败里 47% 是方法错，31% 是理解错，22% 是执行错。瓶颈在专业判断，不在会不会敲命令。所以难度要来自决策点，而不是步骤数。

### 2.2 一个家族怎样变成成千上万道题

```
设计规格 ──► 家族 = generate(seed, level) ──► Harbor 任务目录
               │
               │  seed   换数据，换哪个样本、哪个基因、哪块板带问题
               │  level  同一个种子上逐级加深，或逐级减少文字
               ▼
          放行关卡 G1–G7（全自动）──► 难度筛选 G8 ──► 入库
```

一个家族由五样东西组成，都是代码：

- **生成器**：先定答案（哪些变异是体细胞的、每个基因的效应量、每个化合物的效力曲线），再正向模拟出输入数据。
- **未披露的决策点**：数据里藏的问题。题面不提，但每一个都必须能被专业人员的常规质控发现，这条“从哪里能发现”的实测证据随题目存档。
- **参考解法和独立第二解法**：两条不同的正确路线，都必须满分。第二解法防止评分器只认一种做法。
- **评分器**：确定性的程序评分，硬门槛加带容差的连续分。
- **攻击清单**：空提交、抄输入、先验常数答案、每个决策点单独被忽略的粗心做法、刚好超出容差的结果。

规模来自三层相乘：**家族**（写一次）× **种子**（实例）× **难度档**（课程）。

### 2.3 保证题是对的：七道自动关卡

`python -m alegen make <家族> --seed N --level L` 一条命令生成并校验，任何一道不过就不放行。

| 关卡 | 检查什么 |
|---|---|
| G1 | 镜像能构建 |
| G2 | 参考解法在断网容器里得分 ≥ 0.99 |
| G3 | 植入真值、容差内的扰动、独立第二解法都满分 |
| G4 | 攻击清单里的每一种提交都低于各自的上限 |
| G5 | 评分器对同一份提交重复评分结果相同 |
| G6 | Harbor 自身运行：oracle = 1，nop = 0 |
| G7 | 题面承诺的工具在登录 shell 里可用 |

### 2.4 难度阶梯：七档，其中两档零成本

| 档位 | 怎么来的 | 数据和真值 |
|---|---|---|
| L1–L3 | 作者写的三档：无决策点 → 全部决策点 | 各档不同 |
| L4 | 作者加深：新的决策点，更长的链条 | 新数据 |
| L5 | 自动删掉写明的验收判据、核对流程和审计清单 | 与上一档逐字节相同 |
| L6 | 再自动删掉实验记录里指路的句子，证据只留在数据里 | 与上一档逐字节相同 |
| L7 | 作者新埋一个没有任何文字提示的坑 | 新数据 |

L5、L6 是纯文本变换（`alegen/descaffold.py`），任何家族写好最难一档后自动得到，不需要再出题。同一个种子的各档构成一条课程，可以按模型当前的水平取样。

### 2.5 难度筛选：用标尺模型把难度量出来

G1–G7 保证一道题是对的，但不说明它难不难。按结构算的事前难度被实测否定了两次，所以第八道关卡直接量（`alegen/g8.py`）：

- 通过 G1–G7 的实例，标尺模型至少两次尝试**全部不过**才留作难题；全过则淘汰；有过有不过记为不稳定。
- 要求每次都不过，是因为同一个模型在同一道题上出现过 1.0 和 0.6，只凭一次失败筛，留下的是运气差的实例。
- 先过 G1–G7 再筛，是因为这种筛选最容易留下的恰恰是坏题和有歧义的题。有一个种子就是在 G4 被拒的，不管模型在它上面得几分。

### 2.6 为什么这些题适合当强化学习的训练数据

- **奖励有梯度。** 分数是 0–1 的连续值，每个分量在“满分容差”和“零分容差”之间线性过渡。这 15 道题上 52 次没过的尝试里，39 次得分在 0.2–0.8 之间，9 次是 0 分（多数是没交卷）。
- **奖励刷不上去。** 每道题放行前有 14–27 种走捷径的提交被证明拿不到分；真值只在评分镜像里，agent 的容器里没有，运行时断网。
- **奖励是确定的。** 全部是程序评分，没有 LLM 评委；同一份提交永远得同一个分。
- **答案背不下来。** 按种子换数据、换带问题的对象，同一个工作流可以出任意多个不同的实例。
- **是长程任务。** 这 15 道题上 61 次有分数的尝试，中位用时 25 分钟、52 轮，四分之一超过 70 分钟，上限是 2 小时。
- **环境可以反复重置。** 每道题是一个自包含的 Harbor 任务目录，容器起停互不影响。

奖励目前只在一局结束时给一次。**这些题还没有真的用来训练过模型**，所以“能提升能力”是设计上的论证，没有训练实验的证据。

### 2.7 规模和成本：实测数字

| 项目 | 实测 |
|---|---|
| 已通过全部关卡的实例 | 77 个不同的（家族、种子、难度档）组合，覆盖 10 个家族、7 个难度档 |
| 被关卡拒收的实例 | 1 个（一种较弱的统计做法在那个种子上也能满分） |
| 生成一个实例 | 几秒到几分钟 |
| 一个实例过完关卡 | 中位 4.4 分钟（最短 0.3 分钟，最长 49.5 分钟） |
| 每个实例自带的攻击提交 | 中位 17 种（6–27 种） |
| 写一个家族 | 十个家族里八个由并行的 agent 按 `pipeline/AUTHORING.md` 写成，再由同一套关卡验收；三个 L7 新坑各用了一个到一个半小时 |
| 难度筛选 | gemini-3.8-flash 每次尝试约 1.2 美元、10–20 分钟，每个实例两次 |

- **瓶颈不在出题，在两头。** 一头是新家族的设计和验收，需要有人判断“这个坑公不公平”；另一头是难度筛选的模型调用。中间的生成和校验是全自动的。
- **按实测外推（没有实际跑过）**：现有 10 个家族各取 100 个种子、5 个难度档就是 5,000 个实例，按中位 4.4 分钟算，校验约 370 个机器小时，可以并行。难度筛选不必逐个做，每个家族每档抽几个种子即可。
- **加一个新家族的步骤**：写一份规格 → 作者（人或 agent）按规范实现生成器、两个解法、评分器和攻击清单 → `alegen make` 过关卡 → 展开种子和难度档 → 抽样做难度筛选。

## 3. 十五道题：难度系数与 flash 模型得分

- **事前难度**：由参考解法的结构算出（工具调用数、工具数、决策点数、运行时长），题目一生成就有。实测表明它不可靠，只代表出题意图。
- **难度系数 = 1 − gemini-3.8-flash 的平均得分**（事后难度，按该题常规轮数上限下的尝试计算），0 是每次满分，1 是每次 0 分。它和“是否通过”是两回事：crispr L6 的系数只有 0.25，因为模型每次都拿到 0.75，但一次也没过线。

读表时要知道的几点：

- **这些题不是谁都做不出。** crispr 的去提示版（种子 1）Kimi 和 Qwen 满分；rnaseq 的去提示版 DeepSeek 和 Qwen 满分（种子 1），GLM 满分（种子 3，12 轮）；trio 的 DeepSeek 满分；hcs L6 Kimi 得 0.955（它每轮慢，但只用了 50 轮），Gemini 在 300 轮上限下也满分。这是“题目可解、分数可达”的独立证据。

## 4. 每个家族考什么，flash 模型错在哪

下面的失分原因都来自轨迹和评分明细（`results/jobs/`），不是推测。

| 家族（本包题数） | 工作流 | 拦住模型的那一步 | Gemini 实际怎么做的 |
|---|---|---|---|
| `somatic_tn`（2） | 肿瘤/正常配对：FASTQ → 比对 → 体细胞突变 | 一个病人的肿瘤文库带与读段方向相关的假象（脱氨、氧化），正反链计数是平衡的，默认过滤看不见 | 配对查对了，标准流程加默认过滤，精确率分量为 0（种子 1 的精确率是 0.68）；两个种子、四次尝试的得分都在 0.554–0.556 |
| `trio_liftover`（2） | 罕见病家系：hg19 的 VCF 转到 GRCh38 再筛候选变异 | 两个参考版本之间碱基不同的位点、一段方向相反的区块，转换工具默认不处理 | 种子 1 的 13 个候选漏 1 个、多报 1 个（0.718）；种子 2 整个变异集都不对（0.080）；两个种子的第二次尝试都用满 150 轮没交卷 |
| `crispr_screen`（3） | 接手一个混合文库 CRISPR 药物筛选：重新计数、判断哪些文库加了药、找增敏和耐药基因、写勘误 | 样本表里有两份文库与实际不符；题面不再提“样本管重新排过架” | 按样本表分组，药物效应被稀释，基因效应量一项为 0（0.750）；它用参照基因自检，40 个全对，于是交卷 |
| `rnaseq_confound`（3） | 接手一个 RNA-seq 项目：重新定量、身份核对、差异表达、写勘误 | 建库批次与处理部分混杂，必须放进模型；题面不再有审计清单 | 找对了被对调的样本和混合文库，但没把建库批次放进模型，多出 47 个假阳性（0.706）；种子 3 连样本标签也没改对（0.514） |
| `flow_compensation`（2） | 八色流式：由单染对照算补偿、设门、报群体比例 | 两个样本在采集中段有一段时间某条激光线的信号掉到三四成，只有按 Time 轴看信号才能发现 | 补偿矩阵全对，从不按时间检查信号，受影响的两项为 0（0.472）；DeepSeek、MiniMax 同样 |
| `hcs_dose_response`（3） | 高内涵筛选板：图像 → 经人工计数验证的细胞计数 → IC50/GI50 | L6：预训练的 Cellpose 直接用不达标，必须对照人工计数反复改进，工作量大。L7：培养板在显微镜上放反了 180°，板位表与图像对不上 | L6：150 轮内两次都没做完（300 轮时满分；Kimi 用 50 轮做出）。L7：看到了“溶剂对照孔没有信号”“读数随浓度上升”，解释成边缘效应和染色梯度，报告全部无活性（0.10–0.28） |

每道题未披露的决策点、各自“从哪里能发现”的实测证据，在该题的 `tasks/<id>/README.md` 里逐条列出。

## 5. 题目准确性与评分（judge）

**通用规则**（`REPORT.md` 第 3.3 节）：

1. **真值是植入的量。** 生成器先定答案（哪些变异是体细胞的、每个基因的效应量、每个化合物的效力曲线），再模拟出数据。隐藏参考不经过任何比对、定量或拟合流程。
2. **全部是确定性的程序评分，没有 LLM judge。** 结构是“硬门槛 + 加权连续分”：文件缺失或格式不可解析直接 0 分；每个分量在“满分容差”和“零分容差”之间线性过渡。
3. **取最差样本，不取平均。** 一个样本做错不能被其他样本平均掉。
4. **容差有实测依据。** 每个家族用参考解法、独立第二解法和每种粗心做法在两个种子上的实测值来定容差，记录在 `docs/families/<family>.md`。
5. **答案材料只在评分镜像里。** agent 的容器里没有真值，运行时断网。

## 6. 练的是 ALE 衡量的哪些能力

内容不与 ALE 的 12 道 life_sciences 题重复（没有复用它的数据集或交付物定义），对齐的是它的形式和它失败分析里的能力。

| 能力 | 对应的 ALE 失败类别 | 本包里承载它的题 |
|---|---|---|
| 用数据核对别人给的表格，而不是照单全收 | 理解：未核实的输入假设 | crispr L6（样本表）、hcs L7（板位表）、somatic（配对清单）、rnaseq（样本标签） |
| 分析前做逐样本质控并据此改方案 | 方法：选错策略（30%） | flow L7（按时间看信号）、somatic（按读段方向看支持读段）、rnaseq（批次进模型） |
| 知道工具的默认行为在哪里不够用 | 理解：领域知识缺口（25%） | trio（参考版本差异）、somatic（默认过滤） |
| 用现有对照验证自己的方法，不达标就改 | 方法：结果未验证 | hcs L6/L7（对照人工计数验证分割） |
| 长流程里不中途放弃、不编造 | 方法：中途放弃（17%）；理解：编造（6%） | 全部：真值植入，编造的数值过不了容差；hcs、trio 的工作量会用满轮数 |
| 严格的输出合约 | 执行：输出格式（10%） | 全部：格式是硬门槛，但接受等价写法（行序、额外列） |

**为什么能泛化。** 每个家族按种子换数据、换哪个样本或哪个基因带问题，答案背不下来；同一个家族有 3–7 个难度档，可以当课程用；L5–L7 的题面不提示该查什么，模型只能学会“先核对再分析”这个习惯本身。

## 7. CLI、GUI 与专业模型

- **CLI 专业软件**（全部 15 道）：bwa、minimap2、samtools、bcftools（含 liftover、csq 插件）、Picard、cutadapt、MAGeCK、salmon、pyDESeq2、FlowKit、scikit-image。
- **专业模型**（hcs 的 3 道）：Cellpose。镜像里装了预训练的 `nuclei` 和 `cyto3` 模型，不能联网下载。预训练模型直接用在这种染色上达不到 SOP 的验证标准，agent 必须对照人工计数判断它哪里错、调参或换成自己写的方法。
- **GUI**：本包 15 道里**没有** GUI 题。整套题里有一个 GUI 家族（`variant_review`，在 IGV 里逐条复核变异），但 Gemini 两次都满分，所以没有进入“最难 15 道”。而且纯文本 agent 是绕开界面做出来的（手工拼 JVM 类文件调用 IGV 自带的读取库），这道题目前并不强制使用界面。经过见 `REPORT.md` 第 8.3 节第 4 点。

## 8. 这轮工作得到的认识

1. **难度来自“没人提醒的那一步”，不是步骤多。** 对照实验里每次只改一样东西：删掉写明的验收判据没有用；把三道题拼成一个项目没有用；删掉告诉模型“该查什么”的句子、或埋一个没有文字提示的坑才有用。
2. **新坑要埋在模型本来不会看的地方。** 同样是“表格与数据不符”，放在 crispr 的样本表和 hcs 的板位表上拦住了 Gemini；放在扩增子的空白对照上没有，因为常规流程本来就要逐个看空白对照。
3. **模型会看见证据而不下结论。** hcs L7 的四条轨迹里它都注意到了异常，其中一次明确问过“剂量序列是不是反了”，然后用“边缘效应”解释过去。训练数据应该奖励“把异常追到底”。
4. **难度必须实测，而且要重复测。** 按结构算的事前难度被两轮实测否定；同一个模型在同一道题上出现过 1.0 和 0.6。所以难度筛选要求标尺模型每次都不过。
5. **先保证题是对的，再筛难度。** 只按“模型做不出”筛，最容易留下的是坏题和有歧义的题。本流程里有一个种子就是在 G4 被拒的，不管模型在它上面得几分。
6. **时限乘以模型速度是一条独立的难度轴。** 同一道题对一个模型是二十分钟，对另一个是两小时装不下。报难度时必须连同时限、轮数上限和 agent 框架一起报。
7. **删掉别的读取工具，不等于强制用 GUI。** 要让一道题真正要求界面操作，跑分的 agent 得能看图，评分里得有只能从界面上得到的信息。

## 9. 局限和没有验证的地方

- **没有做训练实验。** “这些题能泛化地提升 ALE 衡量的能力”目前是设计上的论证和能力映射（第 6 节），没有用它训练过模型来验证。
- **这 15 道里没有 GUI 题。** 整套题里有一个 GUI 家族，但它没有难住标尺模型，而且是被绕开界面做出来的（第 7 节）。
- **选择偏差。** 15 道是按 Gemini 做不出挑的，其中 2 道（rnaseq L5、hcs L6）只有一次有效的失败证据或依赖轮数上限，见下两条。
- **有两对近似重复。** rnaseq L5 和 L6（种子 1）的数据和真值相同，L6 只是再少几句提示；hcs L6 和 L7（种子 1）是同一块板，L7 把图像换了位置。把它们当作同一实例的难度阶梯更合适。
- **hcs L6 的难是工作量。** Gemini 在 150 轮上限下两次都没做完，300 轮时满分；Kimi 用 50 轮、101 分钟做出（0.955）。它难在长程，不难在某个判断，而且结论取决于轮数上限和模型每轮的效率。
- **hcs L7 有一个弱点。** 板放反后，8 个人工标注视野变成了容易的视野，计数验证的把关作用变弱，Gemini 的计数分量因此也丢了分。判定不受影响（计数全对它也只有 0.35），但题目应该修成“标注视野跟着图像内容走”。另有一个继承来的攻击得 0.825，上限为此放到了 0.85。
- **只有 6 个家族。** 另外 4 个家族（amplicon、md、variant_review、xlms）Gemini 两次都满分，没有进入本包。
- **标尺只有一个，每个实例两次尝试。** 换一个模型结论会变：crispr L6（种子 1）拦住了四个模型，没拦住 Kimi 和 Qwen；hcs L6 拦住了 Gemini，没拦住 Kimi。
- **L7 的三个新坑没有经过领域专家审阅**，只过了自动关卡和出题者的核对。
- **数据是合成的**，比真实数据干净；评分偏严，一处出容差通常就低于通过线。
- **没有用各家自带的命令行 agent 跑过**（本机的题目容器不能联网）；terminus-2 是纯文本 agent。
